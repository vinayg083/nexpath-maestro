# NexPath

NexPath is a clean Expo React Native foundation for a path-planning product. It uses Expo Router, TypeScript, NativeWind, Poppins typography, Supabase configuration, and a static light-only design-token palette.

## Current App

- Onboarding starts at `/welcome`; the project index redirects there so the app opens on Welcome with an explicitly bold 28px Reentry Roadmap title before onboardingStep1, onboardingStep2, and onboardingStep3 screens. Finishing onboarding dismisses the onboarding stack before replacing the root with My Path, so native swipe/back actions cannot return to onboarding after completion.
- The onboarding UI follows the uploaded `Untitled4.jpg` reference with minimal white layouts, compact form controls, two-column priority tiles, and small primary action buttons.
- onboardingStep2 loads active goals from `goal_categories`, allows up to 3 local picks (at least 1 to continue), submits selected picks to My Path through `user_path_categories.goal_category_id` only when the user presses Next, and uses an 18px subtitle with two-column category tiles.
- Onboarding uses a fixed header and fixed bottom action area, with only the middle form/options content scrolling.
- Onboarding headers use a shared 26px bold Poppins style.
- The onboardingStep1 form dismisses the keyboard when the user taps outside inputs without pushing up the fixed Next button, requires Month, Year, State, and Area when the selected state has local areas before continuing, saves answers to the signed-in user's `profiles` row before navigating, accepts Month as a name or number while validating it to a backend-ready value from 1 through 12, validates Year as a 4-digit year from 1900 through the current year, and uses 18px field text, lighter Month/Year placeholders, taller birthdate inputs with Month at 50% width and Year at 30% width, a 70% width State dropdown loaded from Supabase, conditional 70% width Area dropdowns loaded from Supabase only for states with local areas, a Supabase-loaded community duration dropdown with no visible placeholder, backend load/save errors shown in red below the final dropdown, capped scrollable dropdown menus, numeric Year keyboard, 2px `#c5ced6` input borders, and opacity press feedback.
- Bottom tab navigation follows onboarding with four sections: myPathScreen, Resources, Calendar, and More.
- The Resources tab is a category-based directory again: `getResourceCarousels()` reads `category_resources`, joins each linked `categories` row and active `resources` row, groups every linked resource under each category, and orders rows by category name plus `category_resources.sort_order`. The screen renders category sections with horizontal resource cards, preserves local directory links for the user's profile location, and keeps task-resource vertical feeds isolated to My Path task resource screens.
- My Path reads the signed-in user's rows from `user_path_categories`, joins each row to `goal_categories`, counts linked `path_tasks`, and calculates progress from `user_path_task_completions` joined back through `path_tasks.goal_category_id`. Each My Path load also updates the signed-in `profiles.timezone` field from the device/browser IANA timezone when available. Category task lists load the backend category and linked `path_tasks` together so the category title never flashes a placeholder; task/resource viewer titles are rendered from backend task data only. Task rows use 2px `#788896` borders, show non-interactive completion circles, and open task detail when pressed. Task subtitles map from `path_tasks.subtitle`, incomplete task action labels map from `path_tasks.incomplete_label`, and completed tasks show `Completed` with a warning before marking them incomplete again; users can only change completion from the task detail screen. Task resources are loaded from `path_task_resources` in backend `sort_order` and shown through a dedicated full-screen vertical feed from the task detail "Let's Go!" action. Each task resource fills the viewport, supports paged swiping as the only navigation while browsing resources, uses a tighter title/description/action layout with no decorative resource images or provider labels, opens hotline/website actions from a lower button, and renders `video` resources directly as full-height player pages instead of showing the intermediate action layout. Shared video playback lives in `components/resources/VideoPlayer.tsx`; it accepts `video_url`, automatically detects YouTube URLs versus direct video/storage URLs, uses `expo-video` with native controls for direct playback, and uses `react-native-youtube-iframe` with validated extracted video IDs for YouTube playback. Direct videos support autoplay while active, center tap-to-play/pause with a fading play overlay, native scrub/seek, fullscreen, mute/unmute, current time/duration controls, loading/buffering UI, retryable errors, web-safe default mute, and pause on inactive/unmount. YouTube videos stay inside the app and are controlled through the YouTube player's own embedded controls, with nothing in the app overlaying the player's touch area. On iOS/Android playback autoplays while the page is active and pauses when it isn't; on web (where browsers block outside control of the embedded player) the video starts with one tap on YouTube's play button and stops when the user scrolls away. Loading, retryable errors, and invalid URL handling are shown around the player. Video player pages show the resource title and description as plain bottom-left caption text with no translucent backing panel; descriptions are capped at 3 lines until tapped to expand, and the caption/chrome overlays never intercept taps meant for the player. The feed includes a final end-of-feed page with a top-right Close/X control and Back button.
- The My Path bottom CTA says `Explore` when the user's path is empty and `Explore More` once path categories exist. `/explore` lists all `goal_categories` with a My Path-style row that shows category icon, title, subtitle, and chevron. `/explore/[id]` uses a task-detail-like layout for category details, with category title, subtitle/description text, and an `Add to My Path` button 40px below the description; categories already in the user's path show a disabled `Added to My Path` action.
- My Path analytics record `task_completed` with task/category metadata, `task_resource_viewed` when task resources are viewed or acted on in the task resource feed, and `task_added_from_explore` when a user adds an Explore category to My Path.
- The Calendar tab stores appointments/reminders in Supabase and only allows strictly future local date-times. The date picker blocks past dates, the time picker keeps its original wheel-style UI, the form shows "Please select a future date and time." below the time field when the selected local time is in the past, and submit validation rejects stale selections.
- The More tab exposes account deletion; before invoking the `delete-account` Edge Function, the client removes the signed-in user's app rows from appointments, devices, My Path categories, task completions, and profile data so Supabase auth deletion is not blocked by related records. After a successful delete and local sign-out, the user is routed back to the Welcome screen.
- Each section has a minimal placeholder screen with a title, subtitle, icon, and "Foundation preview" note.
- The app is light-mode only. Colors are centralized around the requested palette: primary `#336699`, background `#FFFFFF`, text `#293845`, and red `#D3455B` for destructive/accent states.
- Poppins is loaded through Expo Fonts and used across app text.
- Shared form labels use 14px Poppins with a 20px line height.
- Supabase is configured through `lib/supabase/` with validated Expo public env vars, an initialized `@supabase/supabase-js` client, persistent auth sessions, native token refresh handling, and automatic anonymous sign-in on app launch. Anonymous session setup also idempotently ensures the signed-in user's `profiles` row exists before profile-dependent writes such as device registration, onboarding saves, priority picks, My Path reads, profile timezone updates, and task completion writes. onboardingStep1 reads active `states` rows, conditionally reads active `areas` rows for states with local areas, reads active `community_durations` rows for the community duration picker, and updates the signed-in user's `profiles` row with `birth_month`, `birth_year`, `state_code`, `area_id`, `community_duration_id`, and `onboarding_step: 1` before moving to onboardingStep2. onboardingStep2 reads `goal_categories`, hydrates existing picks from `user_path_categories`, and syncs My Path goal category rows only when the user presses Next.

## Structure

- `app/index.tsx` redirects to `app/welcome.tsx`, the dedicated Welcome onboarding screen.
- `app/onboarding/*.tsx` contains the onboardingStep1, onboardingStep2, and onboardingStep3 onboarding screens.
- `components/onboarding/` contains reusable onboarding layout and choice components.
- `app/(tabs)/_layout.tsx` defines the bottom tab navigator.
- `app/(tabs)/*.tsx` contains the four tab screens.
- `app/explore/` contains the goal-category browser and category detail add-to-path flow.
- `components/layout/NexPathPlaceholderScreen.tsx` is the reusable screen layout.
- `lib/nexpath-tabs.ts` centralizes tab metadata.
- `lib/supabase/` contains Supabase env validation, the initialized client, anonymous auth startup with profile-row creation, onboarding option/category queries, priority and profile helpers including timezone updates, Resources category-resource carousel/directory helpers, My Path category/task/resource helpers, and typed table definitions for `states`, `areas`, `community_durations`, `profiles`, `categories`, `category_resources`, `category_placements`, `goal_categories`, `path_tasks`, `path_task_resources`, `user_path_categories`, and `user_path_task_completions`.
- `lib/design-tokens.ts`, `tailwind.config.js`, and `global.css` define the static light palette and typography tokens used by navigation, NativeWind, and shared components.

## Environment

Supabase requires these public Expo variables:

- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_ANON_KEY`

The `.env` file also keeps `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `EXPO_PUBLIC_SUPABASE_REST_URL`, `API_URL`, and `ANON_key` as compatibility aliases for the current Draftbit/Supabase setup. `app.config.js` exposes Supabase values through Expo `extra` as a runtime fallback.

## Draftbit

This app was built with Draftbit, Expo, and React Native. Use Draftbit Publishing for web deploys and native builds.
