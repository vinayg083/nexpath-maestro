# About this app

This file describes this app's stack, structure, and conventions. **Keep it updated**: when the app gains a backend, new conventions, or significant structure, update this file (and the README) so future sessions inherit that knowledge.

## Stack

- Expo cross-platform app (iOS / Android / Web), TypeScript (strict), Expo Router v4 (file-based routing)
- NativeWind v4 (Tailwind for RN) for styling
- React Native Reusables (shadcn-style primitives, `@rn-primitives/*`) as the base component library; build higher-level components on top
- Yarn Berry (v4.x) with **Plug'n'Play** — not classic yarn, no traditional `node_modules`. Patching dependencies is a last resort; use `yarn patch`, never hand-edit.
- React Query available for server state when a backend is wired
- Supabase JS client is configured in `lib/supabase/` for database/auth/storage access
- `~/*` aliases the project root (see `tsconfig.json`), e.g. `import { Button } from '~/components/ui/button';`

## Light-Only Styling

This app intentionally has no dark mode, theme provider, theme toggle, or appearance listener. Expo is configured with `userInterfaceStyle: "light"`, the root layout uses a dark-content status bar, and all screens should keep a white/light background.

Use NativeWind classes (`text-foreground`, `bg-background`, `text-h1`, `border-border`, …) for styled UI. These resolve to static light values declared in `tailwind.config.js` and `global.css`. For raw values in React Native style objects, use `lib/design-tokens.ts`. Do not add `useColorScheme`, `Appearance`, `dark:` classes, or new dynamic theming logic unless the product direction changes.

## Conventions

- **Icons:** Lucide icons must go through the `LucideIcon` wrapper so NativeWind classes apply — `import LucideIcon from '~/lib/icons/LucideIcon';` then `<LucideIcon name="Home" className="h-6 w-6 text-foreground" />`. Do NOT import from `lucide-react-native` directly. Validate the `name` against the wrapper's registry before use; if a name is missing, pick a supported one.
- **Portals:** web uses `WebPortalContext` (DOM container); native uses `PortalHost` from `@rn-primitives/portal`. Both are configured in `app/_layout.tsx`, and the primitives in `components/ui/` rely on this — don't bypass it.
- **Fonts:** Poppins is the app-wide Google Font, loaded in `app/_layout.tsx` with Expo Fonts. Typography utilities in `global.css` and raw style tokens in `lib/design-tokens.ts` should stay aligned with Poppins; use NativeWind weight classes (`font-bold`, `font-medium`, etc.) rather than inline font-family overrides when possible.
- **Navigation:** set an explicit human-friendly `title` for every screen header — never let route names like `(tabs)` or `products/[id]` appear in the UI. Keep `app/index.tsx` for redirects, not feature UI; use `_layout.tsx` files for stacks/tabs.
- **Screens:** wrap in SafeAreaView (react-native-safe-area-context) and handle scrolling/gestures correctly. Keep bottom tab bars compact — pad content inside screens, not via `tabBarStyle`.
- **Components:** shared UI in `components/ui/`, layout-level pieces in `components/layout/`. Keep components small and focused; reuse before creating.
- **Performance:** `FlatList`/`SectionList` for long lists — never `ScrollView` + `.map()` for large collections.

## Critical files

- `app/_layout.tsx` — root layout, light status bar setup, font loading, portal hosts
- `lib/design-tokens.ts` — raw light palette and typography values for React Native style objects
- `tailwind.config.js` — NativeWind config, static light color declarations, safelist
- `lib/utils.ts` — `cn` helper for class merging
- `global.css` — global CSS and typography classes

- NexPath first build is implemented as a static, navigable Expo Router app with onboarding followed by bottom tabs.
- `app/index.tsx` redirects to `/welcome`, so the app always opens on the dedicated Welcome screen with an explicitly bold 28px Reentry Roadmap title before onboarding. Additional onboarding routes live under `app/onboarding/`: `onboardingStep1`, `onboardingStep2`, and `onboardingStep3`; finishing onboarding dismisses the onboarding stack before replacing the root with `/(tabs)/myPathScreen`, so native swipe/back actions cannot return to onboarding after completion.
- The four onboarding screens were restyled to closely match the uploaded `Untitled4.jpg` wireframe reference: minimal white screens, compact form controls, two-column priority tiles, and small primary action buttons.
- onboardingStep2 loads active goals from `goal_categories` — RLS hides inactive rows so no `is_active` filter is needed — allows up to 3 picks locally (at least 1 to continue), and submits the selected picks to My Path through `user_path_categories.goal_category_id` only when the user presses Next. Uses an 18px subtitle; category tiles use `OnboardingChoice`.
- Onboarding screens use `components/onboarding/OnboardingFrame.tsx`, which keeps the title/description header and bottom action area fixed while only the middle content area scrolls.
- Onboarding headers use a shared 26px bold Poppins style.
- `components/onboarding/OnboardingFrame.tsx` supports opt-in keyboard avoidance and tap-to-dismiss behavior; `app/onboarding/onboardingStep1.tsx` uses tap-to-dismiss without keyboard avoidance so the fixed Next button does not move, requires Month, Year, State, and Area when the selected state has local areas before continuing, saves answers to the signed-in user's `profiles` row before navigating, accepts Month as a name or number while validating it to a backend-ready value from 1 through 12, validates Year as a 4-digit year from 1900 through the current year, plus 18px field typography, lighter Month/Year placeholders, taller birthdate inputs with Month at 50% width and Year at 30% width, a 70% width State dropdown loaded from Supabase, conditional 70% width Area dropdowns loaded from Supabase only for states with local areas, a Supabase-loaded community duration dropdown with no visible placeholder, backend load/save errors shown in red below the final dropdown, capped scrollable dropdown menus, numeric Year keyboard, 2px `#c5ced6` input borders, and opacity press feedback.
- Routes live under `app/(tabs)/`: `myPathScreen`, `resources`, `calendar`, and `more`.
- The Resources tab is a category-based directory loaded through `getResourceCarousels()`, which queries `category_resources`, joins each linked `categories` row and active `resources` row, groups every linked resource under each category, and orders rows by category name plus `category_resources.sort_order`. The screen renders category sections with horizontal resource cards and keeps local directory links for the user's profile location. The full-screen vertically paged resource feed is reserved for My Path task resources, not the main Resources tab.
- My Path uses `lib/supabase/path.ts` to read the current user's `user_path_categories`, joined through `goal_categories!inner`, with task totals from `goal_categories.path_tasks(count)` and completed counts from `user_path_task_completions` joined to `path_tasks.goal_category_id`. Each My Path load also updates the signed-in `profiles.timezone` field from the device/browser IANA timezone when available. Task lists filter `path_tasks.goal_category_id` using the My Path goal category id and load the backend category before rendering so the category title never flashes a placeholder; task/resource viewer titles render from backend task data only. Task rows use 2px `#788896` borders, show non-interactive completion circles, and open task detail when pressed. Task subtitles map from `path_tasks.subtitle`, incomplete task action labels map from `path_tasks.incomplete_label`, and completed tasks show `Completed` with a warning before marking them incomplete again; users can only change completion from the task detail screen. Tapping "Let's Go!" opens `app/path/[categoryId]/[taskId]/taskResourcesScreen.tsx`, a dedicated full-screen vertically paged task resource feed. Task resources load from `path_task_resources` ordered by backend `sort_order` only, with an end-of-feed page, swipe-only individual resource pages without a Close/X control, tighter title/description-first pages without decorative resource images or provider labels, bottom action buttons for hotline/website resources, and text-only pages. `video` resources render directly as full-height player pages instead of showing the intermediate action layout. Shared video playback lives in `components/resources/VideoPlayer.tsx`; it accepts `video_url`, automatically detects YouTube URLs versus direct video/storage URLs, uses `expo-video` with native controls for direct playback, and uses `react-native-youtube-iframe` with validated extracted video IDs for YouTube playback. Direct videos support autoplay while active, center tap-to-play/pause with a fading play overlay, native scrub/seek, fullscreen, mute/unmute, current time/duration controls, loading/buffering UI, retryable errors, web-safe default mute, and pause on inactive/unmount. YouTube videos stay inside the app with muted autoplay requested only after the iframe is ready, center tap-to-play/pause with a fading play overlay, embedded fullscreen and mute controls, loading, retryable errors, invalid URL handling, a tap-to-play fallback when YouTube/WebView autoplay policy blocks startup, and pause on inactive/unmount. Video pages show the resource title and description as plain bottom-left caption text, with no translucent backing panel and descriptions capped at 3 lines until tapped to expand. The end page includes a top-right Close/X control and a Back button.
- The My Path bottom CTA says `Explore` when the user's path is empty and `Explore More` once categories exist. Both states route to `/explore` with the same arrow icon.
- `/explore` is a full goal-category browser backed by `goal_categories`, using the same title/subtitle query shape as onboardingStep2. It lists all goal categories, including ones already in My Path, with `ExploreCategoryRow`, a My Path-style row that shows the category icon, title, subtitle, and chevron. `/explore/[id]` mirrors the task detail layout for category details: category title, subtitle/description text, then an `Add to My Path` button 40px below the description; it has no task title, resource link, or completion button. If the category is already in the user's path, the action is disabled and reads `Added to My Path`.
- My Path analytics use `lib/analytics`: task completion emits `task_completed` with task/category metadata, task resource feed views and resource action taps emit `task_resource_viewed`, and Explore add-to-path emits `task_added_from_explore` with category metadata.
- The Calendar tab creates Supabase-backed appointments/reminders and requires strictly future local date-times. `AppointmentDateField` prevents past dates, `AppointmentTimeField` keeps the original wheel-style time picker UI, `CalendarScreen` shows "Please select a future date and time." below the time field when the selected local time is in the past, and submit revalidates with the user's local `Date` before saving.

After a successful delete and local sign-out, the user is routed back to the Welcome screen.
